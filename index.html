Distributed Rate Limiter + Analytics Pipeline

Go · Redis · Python · PostgreSQL · Next.js · Docker · Fly.io

  • Built a distributed rate limiter in Go + Redis with fixed-window, sliding-window, and token-bucket algorithms as atomic Lua scripts (consistent under load, no distributed locks); load-tested with k6 at ~5,000 req/s, p95 ~2 ms, and zero failures across ~106K requests.
  • Instrumented every rate-limit decision through an event-sourced metrics pipeline: each decision emits a fire-and-forget event to a Redis Stream, which a Python worker rolls into per-minute PostgreSQL aggregates, keeping telemetry off the latency-critical /check path.
  • Built a live Next.js monitoring dashboard (per-key leaderboard, rejection-rate gauges, per-algorithm p95 latency breakdown) backed by a read-only Go analytics API isolated from the rate-limit hot path.
  • Deployed all three services to production on Fly.io and Vercel, with the limiter load-balanced across two machines as a 9.2 MB static Go binary.
